# Design: CHZZK Sidebar Favorites (Chrome extension)

Generated by /office-hours on 2026-10-07
Branch: feature/favorites
Repo: olkkani/chzzk-favorites
Status: APPROVED
Mode: Builder (open source / Chrome Web Store)

## Problem Statement
On chzzk.naver.com the left sidebar lists followed channels in one flat list. The user wants a separate favorites section above it, managed independently of the follow list. Question raised: can the list be personal rather than tied to a shared account?

Answer: yes. `chrome.storage.sync` binds data to the user's Chrome profile (Google sync), needs no server, and is private by default.

## What Makes This Cool
The favorites section looks native, as if CHZZK shipped it: grouped (game / chat / support), drag-to-reorder, live status, dark mode.

## Constraints
- Solo dev, WXT + React 19 starter already scaffolded (`entrypoints/`, `wxt.config.ts`).
- No server. Depends on CHZZK's DOM and unofficial endpoints, which can break on a CHZZK update.

## Premises (all agreed)
1. Storage: `chrome.storage.sync`, only channel IDs, groups and order (limits: 8KB per item, 100KB total). Tied to the Chrome profile, not the CHZZK account.
2. Differentiator: separate section above the following list + native look + groups + drag sort. Not just reordering.
3. Content script injected into the sidebar; live status from data CHZZK already renders or from public endpoints. Maintenance cost accepted.
4. Chrome Web Store first; Firefox later via WXT from the same code.

## Landscape (standard web search, summaries only, not hands-on tested)
- Cheese Now: popup with collections of followed channels, notifications. Does not touch the sidebar.
- Chzzk Sidebar Shuffler: moves favorites to the top of the existing following list.
- Cheese PIP: favorites (beta) among many tools, 30K+ users.
- Chzzk Following Bookmarks: Chrome bookmark folder approach.
- Apparent gap: separate native-looking section with groups and drag. Unverified; install and try the competitors first.

## Approaches Considered
- A) Minimal list + star button (S): ruled out, near-identical to existing extensions.
- C) Clone CHZZK's native rows (M): ruled out for now, most fragile to DOM changes and offline channels may not be in the DOM. Keep as a possible technique for the live badge.
- **B) Own React section styled to CHZZK, groups + dnd-kit, live status (M-L): chosen.**

## Recommended Approach
B, built in stages so something usable exists early:
1. Stage 1: favorites section above the following list, star toggle, storage.sync, live dot.
2. Stage 2: groups, collapse, drag reorder.
3. Stage 3: polish (dark mode, empty/error states), store listing.

## Open Questions
- Which CHZZK endpoints give live status for an arbitrary channel ID, and are they callable from a content script (CORS, cookies)? Or from the background service worker?
- Does the sidebar render offline followed channels, or only live ones? Decides where the star button and offline favorites come from.
- Sidebar is a SPA: how stable is the injection point across route changes (MutationObserver)?
- Polling interval for live status and its cost.
- Name, icon and store listing language (KO first).

## Success Criteria
- Favorites persist across reloads and sync to a second Chrome profile device.
- Section survives SPA navigation and a sidebar collapse/expand without duplicating.
- Looks native in light and dark mode; a stranger can't tell where the native UI ends.
- Published on the Chrome Web Store.

## Distribution Plan
- Chrome Web Store via `wxt zip`; Firefox with `wxt zip -b firefox` later.
- CI: GitHub Actions running `npm run compile` and `wxt build`; manual store upload at first.

## Next Steps
1. Inspect chzzk.naver.com sidebar DOM and network calls (DevTools). Write findings into this doc.
2. Install Cheese Now, Sidebar Shuffler and Cheese PIP and note what they lack.
3. Stage 1 in `entrypoints/content.ts` with a React root mounted above the following list.
4. Storage layer (`favorites` model: groups[], items[] with channelId, order).
5. Stage 2 groups + dnd-kit.

## What I noticed about how you think
- You asked "can my favorites be mine instead of shared through an account?" before asking how to build it. You started from who owns the data.
- You picked "native UI + groups and drag sort" over a live-alert or sharing feature. You care about it feeling like part of the site.
